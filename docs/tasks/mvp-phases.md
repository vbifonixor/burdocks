# Phases of our MVP

0. The setup - tech stack configured into basically an app boilerplate. No internal app architecture decisions made yet, just a "hello world" on our stack. More in [./0-setup.md]

1. Agentic development lifecycle - we will need a process of the agents helping me to define ideas for features first into specs, then into good quality code. All while being token efficient. The whole thing should be rather compact as firstly I don't want to get into tokens/rate limit and secondly long agent-written texts are a mess to maintain and keep in mind for both agents and humans and can get really complex really fast

2. The architecture and basic app body - here we will be thinking about how to organize our app - which routes we should have for an MVP and how the app should look like from the code standpoint, how concerns are separated, etc.

3. The MVP functionality, bit by bit. We will first discuss the full scope of the MVP - brainstorm ideas, figure out which should fit into the initial release and which we should leave for later

4. Releasing, continuous improvement and support - the stage when the app development becomes agile - with backlog and everything. Every feature planned separately, every idea gets prioritised and the implementation is just running the ADLC pipeline and making sure I and agent understand each other well.
